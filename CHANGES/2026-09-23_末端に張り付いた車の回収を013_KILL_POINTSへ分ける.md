# 2026-09-23 末端に張り付いた車の回収を013_KILL_POINTSへ分ける

`02_CHANGE ROAD.vfl`が「レーンの乗り換え」と「車の削除」の2つを持っていた。削除の条件も実態に合っていなかったので、条件を直したうえでノードごと分ける。

## 条件の問題：`next_lane_name`が空であることを要求していた

```c
if (s@next_lane_name == "" && @u >= 0.98) { ... }
```

回収したいのは**末端から動けなくなった車**だが、この条件だと行き先名が残っている車は永久に対象外になる。実際に張り付くのは、

- `s@lane_name`を切り替えたあと`03`が新しいレーンを解決できず、`lane_changed`が1のまま固着した車。`next_lane_name`は前のレーンの値が残ったまま
- `xyzdist`が`hitprim < 0`を返し、`@u`が前フレームの値のまま止まっている車

どちらも`next_lane_name`は空ではない。

`@u >= 0.98`も緩く、健全な車が乗り換える直前（`>= 0.99`で乗り換え）と区間が重なっていた。

## 変更内容

### 条件

- `next_lane_name`は見ない。**`@u`が末端ちょうど（`>= 0.9999`）**のフレームだけ数える
- 24フレーム → **12フレーム**で削除

健全な車は`uvw.x >= 0.99`で乗り換わるので、末端ちょうどに12フレーム居座ることはない。

`@u == 1.0`の等値比較は浮動小数なので`>= 0.9999`にしている（`xyzdist`の`uvw.x`は末端で1.0に張り付くため意味は同じ）。

### ノードを分ける

`013_KILL_POINTS.vfl`を新設し、**車を消す処理はここだけ**にする。Solverの最後（`012_COLLISION`の後ろ）。

| ノード | 役割 |
|---|---|
| `02_CHANGE ROAD` | レーンの乗り換えだけ。行き止まり判定は`i@lane_dead_end`に写すところまで |
| `013_KILL_POINTS` | 行き止まりレーンの末端に着いた車と、末端に張り付いて12フレーム動けない車を削除 |

02にあった行き止まりの即削除もこちらへ移した。`prim(1, "end", hitprim)`の引き当ては`xyzdist`のついでに02でやるのが自然なので、判定結果だけを`i@lane_dead_end`（点属性）で渡している。013はInput 0だけで完結する。

点が消えるタイミングを1箇所に集めたのは、同じフレームの下流ノード（`06`の前車検知など）が消える予定の車を見てしまうのを避けるため。

## 確認すること

- 行き止まりレーンで車が消えるか（`02`から移したので、消えなければ`i@lane_dead_end`が渡っていない）
- `i@lane_end_count`が0以外になる車がいるか。増え続ける車がいれば、そこが本当の張り付き
- 健全な車で`lane_end_count`が溜まらないこと（溜まるなら`@u`が末端で止まる区間があるということ）
- `removepoint`はDOP内のGeometry Wrangle向け。POP Wrangleに置くなら`i@dead = 1`に変える（`KNOWLEDGE/Houdini運用メモ.md`）
