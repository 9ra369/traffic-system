# 2026-09-22 右折のyield候補に左折車が残る（next_turnが""のまま）

右折車が、交差する車線の左折車に対して譲ってしまう（`i@ctrl_src == 3` で確認済み）。

## 原因：07の除外条件ではなく、`next_turn`が空

`07_RESOLVE_CONFLICT.vfl`の候補フィルタは以前から`opp_next == "left"`を弾いている。それでも通り抜けるということは、**相手の`next_turn`が`"left"`になっていない**ということ。

候補は`lane_name == opp_lane`で絞られるので、**候補に残る左折車は必ず「まだ手前の直進レーンにいる車」**である（コネクタに乗った瞬間、コネクタは行き先レーンの`lane_name`を継承するので`opp_lane`と一致しなくなり、レーン条件で落ちる）。つまり`opp_turn == "left"`の行は候補に対しては実質効かず、**左折を見分けられるのは`next_turn`だけ**。そこが空なら除外は成立しない。

`next_turn`が空になる経路は2つあった。

1. **スポーン直後**：`next_turn`は`03_UPDATE_LANE_ATTRIB.vfl`の`lane_changed`ブロックでしか作られないので、一度も乗り換えていない車は空のまま（`CHANGES/2026-09-22_スポーン直後にnext_turnが空になる.md`で対処済み）
2. **先読みのprim取り違え**：`nearpoint`で引いた最寄り点のprimを`npr[0]`でそのまま使っていた。同じ`lane_name`を持つprimは「行き先レーン本体」「そこへ入る他のコネクタ」も含むため、**行き先レーン本体を掴むと`turn`(prim)を持たず`next_turn`が`""`のまま残る**。エラーは出ない

## 変更内容

### 03_UPDATE_LANE_ATTRIB.vfl：先読みするコネクタを選び直す

`nearpoints`で近い順に8点見て、

1. `is_connector == 1` のprimだけを対象にする（行き先レーン本体を除外）
2. そのうち `prev_lane == i@lane_id`、つまり**自分のレーンから出ているコネクタ**を採る
3. 一致が無ければ最初に見つかったコネクタ（既にコネクタ上にいるときは`prev_lane`が自分の`lane_id`と一致しないため、この保険が要る）

`prev_lane`は`11_CONNECT_LANE.vfl`が入口点の`lane_id`としてコネクタprimに焼いている。位置の近さではなく**接続関係**で選ぶので、交差点の形に依存しない。

### 07_RESOLVE_CONFLICT.vfl：条件を明示形にし、除外数を数える

```c
int opp_straight = (opp_turn == "straight" || opp_turn == "");
if (opp_turn == "left" || opp_turn == "right") { dbg_n_turnout += 1; continue; }
if (opp_straight && (opp_next == "left" || opp_next == "right")) { dbg_n_turnout += 1; continue; }
if (point(0, "rt_lookahead", pt) == 1) { dbg_n_turnout += 1; continue; }
```

- 直進レーンの点は`turn`が既定値（`""`）のことがあるので、`010_INTEGRATE.vfl`と同じく`""`も直進扱いにする
- `i@dbg_n_turnout`を追加。**この除外で何台落としたかが見えないと、効いていないことに気づけない**のが今回の問題そのものだった

判定の意味は変えていない（`opp_turn`が`"straight"`/`""`以外の候補は上の行で既に落ちるため）。

## 確認すること

- 交差する車線の左折車がいる状態で、右折車の`i@dbg_n_turnout`が1以上になるか。0のままなら相手の`next_turn`がまだ空
- その左折車を1台選んで`s@next_turn`を直接見る（`"left"`が入っているか）
- `i@ctrl_src`が3にならなくなったか
- File Cacheが残っていると03の変更が反映されないので、先頭フレームから流し直す

## 追記：`dbg_n_turnout`が出なかった理由

07のノードに貼られていたコードが`2c7d690`相当（2コミット前）だった。`dbg_n_turnout`どころか**左折除外そのものが入っていない**状態で、`cp_baked != 0`の修正（`c915f87`）も効いていなかった。

ノード側だけ`clear_frames = 15`（gitは導入時から24）になっていたので、VFLを15に合わせてから貼り直す。

貼り直しが必要なノード:

| ノード | 内容 |
|---|---|
| 07_RESOLVE_CONFLICT | 左折除外・`dbg_n_turnout`・`cp_baked != 0` |
| 03_UPDATE_LANE_ATTRIB | `next_turn`の書き込みとコネクタ先読みの選び直し |
| 01_INIT | `next_turn` / `next_lane_name` / `lane_changed` の初期値 |
| 06_CAR DETECT | 右折中の左折車除外 |
| 02_CHANGE ROAD / 010_INTEGRATE | 同じ未コミット分に含まれる |

07だけ貼っても左折除外は効かない（相手の`s@next_turn`を書くのは03）。
