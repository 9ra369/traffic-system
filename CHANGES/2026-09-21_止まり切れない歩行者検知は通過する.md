# 2026-09-21 止まり切れない位置で歩行者を検知したら、止まらずに通過する

横断歩道の直前で急に `ped_crossing` が立つと、`08_STATE.vfl` は距離に関係なく BRAKING に入り、
`required_decel = v^2 / (2 * effective_dist)` がいくらでも大きくなる。09 の BRAKING は
`-required_decel` をそのまま出す（IDM側のような `-b*2.0` クランプが無い）ので、
**横断帯の上で非現実的な急停止**が起きる。

## 方針：07 の交錯点と同じ「止まり切れないなら通過」

右折の交錯点では既に同じ判断を入れている（`07_RESOLVE_CONFLICT.vfl` の `cannot_stop`。
止まり切れないと分かった時点で交錯点上に居座らず抜け切る）。歩行者も同じ理屈が成り立つ:

- 横断帯の上で急停止するほうが危険
- 検知しているのは横断歩道点であって歩行者そのものの位置ではない。歩行者が自車レーンに
  達するまでには時間があるので、通過してしまうほうが結果的に安全

## 変更内容：`08_STATE.vfl`

停止対象の比較に入る前に `ped_pass` を出し、立っていれば歩行者を停止対象から外す。

```c
int ped_pass = 0;
if (i@ped_crossing == 1 && i@car_state == 0) {
    float ped_offset  = 2.0;                   // 下のstop_offset(ctrl_src==2)と揃える
    float brake_decel = f@max_decel * 3.0;     // 緊急制動。07のemerg_decel_ratioと同値
    float stop_dist   = (f@vel * f@vel) / (2.0 * max(brake_decel, 0.01));
    ped_pass = (stop_dist > f@dist_to_ped - ped_offset);
}
```

- **緊急制動は `max_decel * 3.0`**。07 の `emerg_decel_ratio` と同じ値にした。
  巡航用の `max_decel`（0.9〜1.5）で判定すると、まだ余裕がある距離でも「止まれない」と
  誤判定して通過してしまう
- **判定は巡航中(`car_state == 0`)だけ**。07 で踏んだのと同じ理由で、減速開始後に判断し直すと
  「減速 → 止まれないと判定 → 通過 → 加速」の往復に陥る
- 外すのは2箇所。IDMに預けるかを決める `nearest_stop` と、停止対象の比較本体
- `i@dbg_ped_pass` を追加（通過を選んだフレームで1）

## 検証（hython, Houdini 20.5）

`vel=14 / max_decel=1.2` → 緊急制動 3.6 m/s²、制動距離 27.2m。

| `dist_to_ped` | 結果 |
|---|---|
| 60m | `ped_pass=0` / `car_state=1` / `ctrl_src=2` / `required_decel=1.69` → 通常どおり減速 |
| 8m | `ped_pass=1` / `car_state=0` / `ctrl_src=-1` → 停止対象から外れて通過 |

つまり「要求減速度が `max_decel` の3倍を超えるなら通過」。この速度域では残り約29m以内が
通過の範囲になる。広すぎると感じたら倍率を下げる（07側と揃えるかは別途判断）。
