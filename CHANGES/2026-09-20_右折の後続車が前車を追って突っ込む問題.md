# 2026-09-20 右折の後続車が前車を追って交錯点に突っ込む問題

先頭の右折車は直進車を検知して正しく譲る。しかし**その後続の右折車**が、自分でもyieldを立てているのに減速せず、先行右折車を追って交差点に入り直進車と衝突する。

## 原因：`08_STATE.vfl` が「前車の方が近い」だけでyieldを捨てていた

```c
if (i@car_ptnum >= 0) {
    float nearest_stop = ...;              // 信号 / 歩行者 / 交錯点のうち最も近いもの
    if (i@yield_conflict == 1)
        nearest_stop = min(nearest_stop, f@dist_to_conflict);

    if (f@dist_to_car <= nearest_stop) {   // ← ここ
        i@car_state = 0;                   // IDMに丸投げして以降の判定を全部捨てる
        return;
    }
}
```

比較している2つの距離の性質が違う。

- `f@dist_to_car` … **前車まで**の距離（数m）
- `f@dist_to_conflict` … **交錯点まで**の距離（交差点中央なので普通はもっと遠い）

後続車は常に前車を数m前に持つので、`dist_to_car <= dist_to_conflict` がほぼ常に成立し、`i@yield_conflict == 1` が毎フレーム無視される。後続車の制御は「前車へのIDM追従」だけになり、**先行右折車が隙を見て抜けた瞬間に、後続車もそれを追って加速する**。直進車が前車より物理的に近くなっても、07の判断は08に届かないまま。

### 二次被害：解除条件 `cannot_stop` が必ず刺さる

08が早期returnで `i@car_state = 0` を書き込むため、後続車は**キューで停止中でも `car_state == 0`**。07の

```c
int cannot_stop = (i@car_state == 0) && (stop_dist > dCp);
```

は「減速を始めた後は判断し直さない」ためのガードだが、後続車は減速状態に入れないのでガードとして機能しない。交錯点に速度を持ったまま近づく → `cannot_stop` 成立 → `dbg_go_reason = 1` でyieldがgoに落ちる、という片道の流れになっていた。つまり後続車は「減速しないから止まれない、止まれないから譲らない」。

## 変更内容

### 1. `08_STATE.vfl`：抜けていく前車にはyieldを譲らない

```c
float leader_slow = 1.0;   // m/s
int   follow_ok   = (i@yield_conflict == 0)
                 || (i@car_signal == 1)        // 前車が減速/停止（06が front car_state から出す）
                 || (f@car_vel < leader_slow); // 前車がほぼ止まっている

if (follow_ok && f@dist_to_car <= nearest_stop) { ... return; }
```

前車が**実質の停止線として機能しているときだけ**IDMに預ける。前車が走り抜けていくなら早期returnせず、`ctrl_src = 3` / `ctrl_state = 2` の通常のyield制動（停止目標 = `dist_to_conflict`）へ進む。

`i@car_signal` だけでは足りない。3台以上のキューでは2台目も早期returnで `car_state = 0` に固定されるため `car_signal` が 0 のままで、3台目が「前車は抜けていく」と誤認して前車の手前ではなく交錯点を目標に減速してしまう。`f@car_vel`（06が入れる前車の実速度）を併用してこれを塞いでいる。

### 2. `07_RESOLVE_CONFLICT.vfl`：停止中の `t_ego` から `car_state` 条件を外す

```c
// 変更前
if (i@car_state >= 1 && f@vel < vel_stopped) {
// 変更後
if (f@vel < vel_stopped) {
```

上記のとおり後続車は停止中でも `car_state == 0` なので、停止しているのに走行中の式（`time_to_reach` に `vel≈0`）で `t_ego` を出していた。`v_floor = 1` に落ちて `t_ego ≈ e_dist` 秒（20mなら20秒）という非現実的な値になり、`t_other < t_ego + margin` がほぼ常に成立 → 相手が遠くても永久にblockingだった。発進を仮定した `sqrt(2*e_dist/max_accel)` に統一する。

### 3. `07_RESOLVE_CONFLICT.vfl`：`ego_ahead < 0` を通過判定に使えるのは限られた状況だけ

1・2 を入れた結果、後続車で `i@ctrl_src = 3` は立つようになったが、その直後に `i@yield_conflict` が 0 へ落ち `dbg_go_reason = 3`（`ego_ahead < ego_ahead_min`、交錯点を通過した）が記録された。

```c
float ego_ahead = dot(normalize(v@dir), t_cp - @P);   // m（正なら前方）
```

**交錯点はコネクタ（右折カーブ）上にあり、停止線に立つ車から見るとほぼ真横にある。** 右折の交錯点は対向直線レーンとの交点なので、自分のレーンのすぐ隣で、進入方向に対して数mしか前に出ていない。つまり `ego_ahead` は停止線まで詰めた時点で 0 付近をまたぐ。**横に並んだだけで「通過した」と判定される。**

先頭の右折車は手前から減速して交錯点の手前1m（`08` の `stop_offset`）で止まるのでギリギリ正の側に残っていたが、後続車は前車追従で停止線まで詰めてから自分の判断に切り替わるため、切り替わった瞬間にはもう `ego_ahead` が負になっていた。

判定を2段で絞る。

```c
float pass_margin = 2.0;   // m
int   passed_cp   = (s@turn == "right")                          // (1)
                 && (ego_ahead < ego_ahead_min - pass_margin);   // (2)
```

- (1) まだコネクタに乗っていない（`rt_lookahead` での先読み中）なら、交錯点はこれから乗る曲線の上にあるので**通過しようがない**。`s@turn` は `03` が現在のレーンから読み直しているので、コネクタ上でだけ `"right"` になる
- (2) コネクタ上でも、真横ではなく明確に後方（既定2m）へ来るまで待つ

`ego_ahead` を「横ズレの影響を受けない」と書いていた既存コメントも、交錯点が真横にある構成では成り立たないので直した。

解除が遅れる方向の変更なので、安全側には倒れない。行き過ぎても `dCp < stop_margin`（`go_reason = 2`）と `cannot_stop`（同 1）が別に効く。

### 4. `07_RESOLVE_CONFLICT.vfl`：対向車を1台にロックするのをやめる

3 を入れても「後続の対向直進車を検知しない」状態が残った。原因は判断ラッチとは別で、**indexごとに相手を1台だけロックしていた**こと。

```c
int t_id = in_target_id[idx];            // 前フレームにロックした相手
...
if (point(0,"id",pt) == t_id) { target_seen_this_frame = 1; target_pt = pt; }
if (d < nearest_d) { nearest_d = d; nearest_pt = pt; }   // 自車からの距離で次点を選ぶ
...
if (t_id >= 0 && target_pt >= 0) { /* TTCはこの1台に対してだけ */ }
```

先頭の対向車がロックされている間、**その後ろに続く対向車は一度もTTC評価されない**。先頭が `opp_clear` を過ぎてロックが外れたフレームで初めて後続に切り替わるので、判断がその瞬間だけ入れ替わる（「一瞬 後続車に移って、すぐ前車に戻った」の正体）。しかも次点の選び方が**自車からのユークリッド距離**なので、交錯点を抜けて自車の脇を通過中の車が「最も近い」ことがあり、順序として正しくない。

ロックを廃止し、候補を全部同じTTC式で評価する。

```c
// t_egoは相手に依存しないのでループの外で1回
foreach (int pt; cands) {
    ... 同じフィルタ ...
    any_candidate = 1;
    float t_other = time_to_reach(distance(t_cp, opp_p), vel, accel, v_floor);
    if (t_other >= min_t_other) continue;
    min_t_other = t_other;
    t_id        = point(0, "id", pt);   // 最も早く交錯点に来る1台。表示用
}
blocked = (min_t_other < t_ego + safety_margin);
```

`blocked = OR(t_other_i < t_ego + margin)` は `min(t_other)` との1回の比較と**厳密に等価**なので、評価式そのものは従来どおり。代表を「自車から最も近い車」ではなく「最も早く交錯点に来る車」に変えた点だけが違う。

これで先頭・後続を区別せず、どれか1台でもblockingなら yield になる。先頭が抜けても後続が残っていれば判断は連続したままで、切り替わりのチラつきも消える。

ラッチとして残るのは `rt_decided`（yield確定後はgoに自動で戻さない）と `rt_clear_count` だけ。`rt_target_id` / `rt_target_lock` は毎フレーム作り直す表示用の値になった（`21_VIZ_DEPENDENCY` が弧の行き先に使う）。

### 5. `07_RESOLVE_CONFLICT.vfl`：`t_ego` が前車を無視していた

4 を入れても後続の右折車は `i[]@rt_decided == 2`（go）のままで、`dbg_go_reason` は 0、`f[]@dbg_ttc_margin` は負だった。つまり**候補は拾えていて、TTCが「脅威なし」と判定している**。

```c
blocked = (min_t_other < t_ego + safety_margin);
```

`t_other` は先頭車も後続車も同じ相手・同じ `t_cp` なので同値。差が出るのは `t_ego` だけで、**後続車の方が `t_ego` が小さくなる**。

| | 状態 | `t_ego` の式 | 例（`max_accel`=1.0） |
|---|---|---|---|
| 先頭の右折車 | 停止中（`vel < vel_stopped`） | `sqrt(2*e_dist/max_accel)` | `e_dist`=5m → **3.2s** |
| 後続の右折車 | 前車に追従して走行中 | `time_to_reach(e_dist, vel, accel)` | `e_dist`=15m, 5m/s, +1m/s² → **2.4s** |

交錯点から**遠い**後続車の方が、走っているぶん到達時間が短く出る。`blocked = t_other < t_ego + 4` なので、`t_other` が7s前後だと先頭車だけ成立して後続車は成立しない。

原因は `t_ego` が**前方がすべて空いている前提（free run）で外挿している**こと。実際には後続車は前車より先に交錯点へ行けない。

```c
float lead_headway = 1.0;   // s
if (i@car_ptnum >= 0 && i@car_is_cross == 0 && f@dist_to_car < e_dist) {
    float t_lead = (e_dist - f@dist_to_car) / max(f@car_vel, v_floor);
    t_ego = max(t_ego, t_lead + lead_headway);
}
```

`06_CAR DETECT` は `07` より先に走るので、`i@car_ptnum` / `f@dist_to_car` / `f@car_vel` はこの時点で今フレームの値になっている。前車が止まっていれば `f@car_vel` が `v_floor` に落ちて `t_lead` が大きくなり、`t_ego` も大きくなる＝blockingが立ちやすくなる。安全側にしか動かない。

`i@car_is_cross == 0` で同レーンの前車に限定し、`f@dist_to_car < e_dist` で前車が交錯点より手前にいる場合だけ適用する。

### 6. `07_RESOLVE_CONFLICT.vfl`：相手の減速を真に受けない

`time_to_reach` は `accel < 0` で判別式が負になると `9999`（手前で止まるので到達しない）を返す。対向直進車がIDMで1フレーム緩んだだけで `t_other` が跳ね上がり、blockingが消える。等速で来た場合の時間と比べて早い方＝安全側を採る。

```c
float t_other = min(time_to_reach(o_dist, o_vel, o_accel, v_floor),
                    o_dist / max(o_vel, v_floor));
```

`t_ego` 側は逆に大きい方が安全なので、こちらの下限は入れない。

### 7. 通過判定が「真横」で誤爆するのを塞ぐ（3 の続き）

5・6 で対向の後続車を正しく追跡できるようになった後も、**追跡中に急に判定が前車へ移る**現象が残った。そのフレームで `i@yield_conflict` が 0、`i@dbg_follow` が 2、`i[]@dbg_go_reason` が 3。つまり 3 で入れた2段のガードを通り抜けて、また `passed_cp` が成立している。

`s@turn == "right"` が条件なので、車は既にコネクタに乗っている。そして「急に」なので離散イベント＝`lane_changed`（コネクタに乗った瞬間）が疑わしい。ここで2つのことが同時に起きる。

- `s@turn` が `"right"` になり、3 で入れた (1) のガードが開く
- `03` が `v[]@rt_target_cp` を**無条件で入れ直す**

#### 7-1. `07`：後方成分が横方向成分を上回るまで通過としない

右折の交錯点は対向直線レーンとの交点なので、**自分のレーンのすぐ隣**にある。コネクタに乗った直後の車から見ると、距離のほとんどが横方向で、進行方向成分はわずかしかない。`pass_margin = 2.0` を置いても、レーン幅ぶんの横オフセットがあれば 2m は簡単に超える。

```c
float lat_cp = length(ego_to_cp - ego_ahead * normalize(v@dir));   // 横方向の距離
int   passed_cp = (s@turn == "right")
               && (ego_ahead < ego_ahead_min - pass_margin)
               && (-ego_ahead > lat_cp);   // ← 追加
```

`-ego_ahead > lat_cp` は「`dir` と `自分→交錯点` の角度が135°より後ろ」と同じ意味で、**真横に並んでいる間は成立しない**。距離ではなく向きで見るので、レーン幅やスケールに依存しない。

#### 7-2. `03`：`rt_target_cp` をラッチと同じ条件でだけ入れ直す

```c
// 変更前：lane_changedのたびに無条件
v[]@rt_target_cp = cross_line_pos_local;
// 変更後：ラッチを積み直す（＝cross_linesが変わった）ときだけ
if (!(same_cross && n_cross > 0)) { ...ラッチ初期化...; v[]@rt_target_cp = cross_line_pos_local; }
```

元のコードは「`rt_target_cp` は同じ値なので毎回代入している」という前提だったが、これは検証されていない仮定だった。`cross_line_pos_local` の引き当ては `nearpoint(1, "@lane_name=" + ..., @P)` → `pointprims(...)[0]` を経由しており、**自車の位置によって別のprimを掴みうる**。コネクタの点は行き先レーンの `lane_name` を継承しているので、行き先の直線レーンとコネクタが同じ名前を共有する点も効いてくる。

交錯レーン一式が同じなら交錯点も同じはずなので、値が変わる＝引き当てが揺れたということ。ラッチを引き継ぐときは `t_cp` も引き継ぐ方が一貫している。

**確認方法**: 判定が飛んだフレームの前後で `v[]@rt_target_cp` が変化していたら 7-2 が原因。変化していなければ 7-1（真横での誤爆）。

## 挙動

先行右折車が止まっている間は従来どおりIDMで詰めて並ぶ。先行車が発進して交錯点を抜けにいくと、後続車はその瞬間に `follow_ok = 0` になり、自分の `dist_to_conflict` を目標に `required_decel` で減速して交錯点手前で止まる。先行車が再び減速/停止すればまたIDM追従に戻る。

## 確認すべきこと

- 2台目以降の右折車で `i@ctrl_src` が 3（コンフリクト）になるフレームがあること。ずっと -1 のままなら早期returnが外れていない
- `dbg_go_reason` が 1 のまま残る後続車がいないこと
- 減速中（`car_state == 1`）は09が前車を見ない定数減速になる。前車が急停止した場合の復帰は「`car_signal`/`car_vel` が落ちて次フレームにIDMへ戻る」頼みなので、追突するようなら `ctrl_state == 2` の停止目標を `min(dist_to_conflict, dist_to_car)` にすることを検討する
- `leader_slow = 1.0` は要チューニング。大きくすると徐行中の前車も「停止線」扱いになり、後続車が自分で譲らなくなる。ヒステリシスが無いので、前車が1.0m/s付近で加減速するとIDM↔自己判断が毎フレーム入れ替わる。チラつくなら閾値を下げる
- `pass_margin = 2.0` の妥当性は `dbg_dcp` と `dbg_ego_fwd` の関係で見る。`dbg_dcp` が数mあるのに `dbg_ego_fwd` が0付近（＝交錯点が真横）なら、まだ通過していない。両者が近い値で揃って負なら本当に後方

## 追加したデバッグ属性

「前車を追い続けている」ときに、08と07のどちらで止まっているかを1回で切り分けるためのもの。本体のロジックには影響しない。

### `08_STATE.vfl`

| 属性 | 意味 |
|---|---|
| `i@dbg_follow` | 追従/自己判断をどの条件で決めたか（下表） |
| `f@dbg_nearest_stop` | `f@dist_to_car` と比較している停止対象までの距離 |

| 値 | 意味 |
|---|---|
| -1 | 前車がいない（`i@car_ptnum < 0`） |
| 0 | 前車を見捨てて自分で判断（`follow_ok = 0`。後続右折車で期待する値） |
| 1 | `follow_ok` だが停止対象の方が近い → 自分で判断 |
| 2 | `i@yield_conflict == 0` なので前車に追従 |
| 3 | 前車が減速/停止中（`i@car_signal == 1`）なので前車に追従 |
| 4 | 前車の実速度が `leader_slow` 未満なので前車に追従 |

`2` が出たら08は正しく、原因は07側（yieldが立っていない）。`3` / `4` なら前車が停止線扱いされている（`i@car_signal` と `f@car_vel` の実値を確認）。`0` / `1` なら08は既に前車を見捨てているので、`i@ctrl_src` は3になっているはず。

### `07_RESOLVE_CONFLICT.vfl`

候補フィルタの段階別通過数。`KNOWLEDGE/デバッグ手法.md` の段階別カウンタの形。

| 属性 | 意味 | 同レーンの前車 |
|---|---|---|
| `i@dbg_n_cands` | `nearpoints` が返した点数（自分を含む）。0なら入力0の配線を疑う | 含む |
| `i@dbg_n_car` | ＋`car == 1` だった点 | **含む** |
| `i@dbg_n_lane` | ＋`lane_name` / `next_lane_name` が `opp_lane` 一致 | **ここで落ちる** |
| `i@dbg_n_alive` | ＋交錯点を抜けていない＝実際にTTC評価した候補 | 含まない |
| `i@dbg_n_cross` | `cross_lines` の本数 | — |

`opp_lane` は対向直進レーンの名前なので、`dbg_n_lane` 以降は**対向直進車しか数えない**。同じレーンの前車も、同じコネクタを通る他の右折車もここで除外される。

`dbg_n_lane` / `dbg_n_alive` は全indexの合計なので、`dbg_n_cross` が2以上なら交錯レーンの本数ぶん足し合わされている。`dbg_n_car` はindexに依存しないので `idx == 0` のときだけ数えている（indexごとに数えると同じ車を重複して数えるため）。

読み方:

- `dbg_n_alive == 1` … 評価できている対向直進車が1台しかない
- `dbg_n_lane` が `dbg_n_alive` より大きい … `opp_clear` で落ちている（交錯点を抜けたとみなされた）
- `dbg_n_lane` と `dbg_n_alive` が同じで少ない … レーン名の一致で落ちている。対向の後続車がまだ上流のレーンにいて `next_lane_name` も一致しない可能性
- `dbg_n_car` の時点で足りない … `search_radius = 40` の外。対向の後続車は遠いので、ここが効きやすい

### `22_VIZ_CROSS_POINT.vfl`（新規）

`v[]@rt_target_cp` をその場に描く可視化専用ノード。`go_reason = 3`（通過判定）が疑わしいとき、**交錯点が本当に対向レーンとの交点にあるか**を目で確かめるためのもの。21_VIZ_DEPENDENCY と同じく **Solverの外側**に置く（点とprimを追加するため）。

交錯点に縦線を立て、車から交錯点へ線を張る。色は `rt_decided`（赤=yield / 緑=go / 灰=none）。primに `cp_ahead`（`dir` への射影）と `cp_lat`（横方向の距離）を持たせてあるので、`-cp_ahead > cp_lat` が成立しているか＝通過判定が立つ条件に入っているかをスプレッドシートで直接読める。

線が対向車線との交点ではない場所を指していたら、`13_BAKE_CROSS_LINES.vfl` の再クックか交点ジオメトリを疑う。
