# 2026-09-21 前車に追従していると、横断歩道の減速開始が間に合わない問題

横断中の歩行者がいるのに、車が横断歩道を踏み越える。デバッグすると `f@dbg_ped_dot`（`v@dir` と歩行者方向の内積）が急にマイナスへ転じており、歩行者が車の**後ろ**に回っていた。同時に `i@dbg_follow` は 0 以外が続いていた＝前車追従（IDM）に預けたままだった。

## 原因：`08_STATE.vfl` の「前車の方が近ければIDMに丸投げ」が歩行者にも刺さっていた

```c
if (follow_ok && f@dist_to_car <= nearest_stop) {
    i@car_state = 0;     // IDMに丸投げ
    return;
}
```

比較しているのは**前車までの距離**と**停止対象までの距離**だけで、「今から止まれるか」を見ていない。

1. 前車が数m前にいる間は `dist_to_car <= dist_to_ped` なので、歩行者を検知していても減速に入らない
2. 前車が横断歩道を抜けて離れていくと、ある瞬間に `dist_to_car > dist_to_ped` へ入れ替わる
3. そこで初めて BRAKING に入るが、そのときには残距離が足りない

[2026-09-20 右折の後続車が前車を追って突っ込む問題](2026-09-20_右折の後続車が前車を追って突っ込む問題.md) と同じ構造。あのときは `follow_ok`（抜けていく前車には譲らない）で yield だけを塞いだが、歩行者・信号には同じ穴が残っていた。

## 変更内容

### 1. `08_STATE.vfl`：停止距離で追従を打ち切る

「今から止まるのに要る距離」を毎フレーム出し、停止対象がそれを切ったら前車が近くてもIDMに預けない。

```c
float brake_ref = f@max_decel * 2.0;   // 09が実際に出す減速度の目安
float stop_need = (f@vel * f@vel) / (2.0 * brake_ref) + f@vel * 0.5 + 1.0;
int   can_defer = (nearest_stop > stop_need);
```

- `brake_ref` は 09 の発散防止クランプ `-b * 2.0` と揃えた。減速度の実効上限がここなので、これ以上の期待をして待つと止まれない
- `f@vel * 0.5` は反応分、`+ 1.0` は 08 の `stop_offset` と対応
- 停止対象がなければ `nearest_stop = 9999` なので `can_defer = 1`。通常の追従は変わらない
- `i@dbg_follow = 5` を追加（停止対象まで余裕がないので自分で止まる）。`f@dbg_stop_need` も出力

### 2. `09_ACCEL.vfl`：BRAKING中もIDMを見る

1 の変更で「前車より遠い停止対象のために減速する」場面が生まれる。ところが BRAKING は `-f@required_decel` しか見ておらず前車を完全に無視するため、前車も歩行者で止まると追突側に倒れる。

IDMの計算を状態分岐の外に出して `a_idm` に持ち、BRAKING では停止用の減速と**強い方**を採る。

```c
if (i@car_ptnum >= 0) f@accel = min(f@accel, a_idm);
```

CRUISING 側は `f@accel = a_idm` に置き換えただけで、値も順序も変えていない（`rt_boost` の上乗せも従来どおり CRUISING のみ）。

## 残っている問題

- **`f@required_decel` が 0→1 遷移時の1回しか計算されない**（`08_STATE.vfl`）。歩行者は動くので目標が近づいてくるが減速率は据え置きのまま。副作用で `09_ACCEL.vfl` の `if (f@effective_dist <= 1)` による 1.2 倍も事実上発動しない
- **`f@dist_to_ped` が歩行者までの直線距離**（`05_HUMAN DETECT.vfl`）。横断歩道までの進行方向距離ではないので、歩行者が横にずれているほど停止目標が奥にずれる
- **前方判定 `dot(v@dir, normalize(to_ped)) > 0.3`**（同）。停止線まで詰めると歩行者は横方向に見えるため、止まれていても検知が落ちて再発進しうる。`v@dir` を normalize していない点も込みで要修正
