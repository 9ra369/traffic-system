# 2026-09-20 右折yieldが距離を残したままgoに倒れる問題

右折車が `rt_decided = 1`（yield）になった直後、交錯点までまだ距離があるのに `2`（go）へ倒れて減速しない。あわせて `dbg_ego_fwd` が `-9999` になり、原因が追えない状態だった。

## 症状の読み方：`dbg_ego_fwd = -9999` は「通過した」ではない

`dbg_*` 各値は `t_decided == 1` のブロックの**中でしか代入されていなかった**。初期値は `-9999` なので、

1. あるフレームで `t_decided` が `1 → 2` に倒れる（この1フレームだけは実値が入る）
2. 次のフレーム以降はブロックに入らないので `-9999` のまま書き戻される

つまり `-9999` は「交錯点を通過したと判定された」ではなく「**もうyieldしていないので評価していない**」を意味していた。倒れた瞬間の値が1フレームしか見えないため、3つある解除条件のどれが効いたのかスプレッドシートから判別できなかった。

## 原因：`cannot_stop` が `max_decel` で判定していた

解除条件のうち `cannot_stop` が、通常の走行速度でほぼ常に成立していた。

```c
float stop_dist  = (f@vel * f@vel) / (2.0 * max(f@max_decel, 0.01));
int   cannot_stop = (i@car_state == 0) && (stop_dist > dCp);
```

`f@max_decel` は `01_INIT.vfl` で **0.9〜1.5 m/s²**、巡航時の快適減速として設定された値である。これで停止距離を出すと:

| 速度 | `max_decel`基準の停止距離 |
|---|---|
| 5 m/s | 8.3〜13.9 m |
| 10 m/s | 33〜55 m |

交錯点は交差点のほぼ中央、コネクタ始点から数m先にある。つまり右折を始めた時点で `dCp` は常に `stop_dist` を下回り、`cannot_stop` が立って初回のyieldがその場でgoに潰れていた。

`max_decel` を基準にするのが誤りで、`08_STATE.vfl` の `required_decel` には上限が無く、`09_ACCEL.vfl` はそれをそのまま（`effective_dist <= 1` では1.2倍して）踏む。実際の車は `max_decel` よりずっと強く止まれる。

なお直前の修正で `dCp < 3.0` の固定値をこの物理判定へ置き換えているが、解除の閾値としては 3.0m 固定より**緩く**なっていた（5 m/s で 8m 以上）。「止まり切れないなら抜ける」の意図に対して判定が早すぎたことになる。

## 変更内容（`07_RESOLVE_CONFLICT.vfl`）

### 1. 制動力に緊急制動の倍率をかける

```c
float emerg_decel_ratio = 3.0;   // チューニング用パラメータとして他と並べて宣言
float brake_decel = f@max_decel * emerg_decel_ratio;
float stop_dist   = (f@vel * f@vel) / (2.0 * max(brake_decel, 0.01));
```

解除の距離が 1/3 になる（5 m/s で 2.8〜4.6 m、10 m/s で 11〜18 m）。`car_state == 0` のときだけ判定する点は変更していない（減速開始後に07が判断し直すと「減速→止まれないと誤判定→go→加速」の片道ループになるため）。

### 2. デバッグ値を毎フレーム出す

`dCp` / `ego_ahead` の計算を `t_decided == 1` のブロックの外へ出した。goに倒れた後も現在値が見えるので、`-9999` は「`t_cp` が未ベイク（原点）」のときだけを意味するようになった。

### 3. goに倒れた理由を保持する `i[]@dbg_go_reason` を追加

`cross_lines` と同indexの配列で、値は倒れたフレームのものが保持される。

| 値 | 意味 |
|---|---|
| 0 | まだ倒れていない（`t_decided` が 0 に戻ると 0 にリセット） |
| 1 | `cannot_stop`：緊急制動でも止まり切れない |
| 2 | `dCp < stop_margin`：交錯点の上にいる |
| 3 | `ego_ahead < ego_ahead_min`：交錯点を通過した |
| 4 | `t_cp` が `{0,0,0}`（`cross_line_pos` 未ベイク） |

4 が出た場合は判断ロジックではなくベイクの問題なので、`13_BAKE_CROSS_LINES.vfl` の再クックを疑うこと。

### 4. 相手が交錯点を過ぎたと見なすまでに車体ぶんの余裕を持たせる

候補探索で、相手の直進車を交錯点通過で候補から外す判定が**相手の先端基準**になっていて、外すのが早すぎた。点は車の先端ではなく車体そのものなので、先端が交錯点を越えてもまだ交錯点上に車体が残っている。

```c
// 変更前：射影の符号が負になった瞬間に外す
if (len_cp > 1e-4 && dot(normalize(opp_dir), to_cp / len_cp) <= 0) continue;
// 変更後：opp_clear（既定5m）ぶん過ぎるまでは候補に残す
if (dot(normalize(opp_dir), t_cp - opp_p) < -opp_clear) continue;
```

あわせて正規化した内積をやめ、`ego_ahead` と同じm単位の符号付き射影に揃えた（閾値をmで書けるようにするため）。

この間 `o_dist = distance(t_cp, 相手P)` は小さいままなので `t_other` も小さく、相手が抜けきるまで `t_lock = 1`（blocking）が維持される。相手が `opp_clear` を越えて離れていけば `t_other` が伸びて自然に解除される。

## 根本原因：右折の判断開始が遅すぎた → `next_lane_name` の先読みを実装

閾値を下げただけでは足りない。**右折車が交錯点の存在を知るのは、コネクタ（右折カーブ）に乗った瞬間だった。** `cross_lines` / `cross_line_pos` はコネクタのprimにしかベイクされておらず（`13_BAKE_CROSS_LINES.vfl`）、手前の直進レーンを走っている間は配列が空で `07` のループが一度も回らない。減速に使える距離が「コネクタ始点から交錯点まで」の数mしかなかった。

さらに `010_INTEGRATE.vfl` の `turn_limit`（`right_turn_speed` へのcrawl）が `i@yield_conflict == 1` のときだけ効くため、**yieldしないと減速せず、減速していないと `cannot_stop` でyieldが解除される**という鶏と卵になっていた。

### 5. `03_UPDATE_LANE_ATTRIB.vfl`：次のコネクタの交錯情報を先読みする

車は常に `s@next_lane_name` を持っている。コネクタの点は行き先レーンの `lane_name` を継承している（`11_CONNECT_LANE.vfl`）ので、**今のレーンを引くのと同じ `nearpoint` を `next_lane_name` に対して撃てばよい**。それだけで、交錯するレーンに入る前から相手を探せる。

```c
int npt   = nearpoint(1, "@lane_name=" + s@next_lane_name, @P);
int npr[] = pointprims(1, npt);
// そのprimのturnが"right"なら、cross_lines / cross_line_pos を借りて rt_lookahead=1
```

引き当てに失敗した場合や次が右折でない場合は `rt_lookahead = 0` のまま、従来どおりコネクタに乗ってからの判断になる（安全側に退化するだけで壊れない）。

### 6. `03_UPDATE_LANE_ATTRIB.vfl`：ラッチを積み直さない条件を追加

先読みを入れると、コネクタに乗った瞬間の `lane_changed` で判断ラッチ（`rt_decided` 等）が0に積み直され、**交差点の中で譲り直しが始まる**。新旧の `cross_lines` が完全一致する場合（＝先読みしていた相手と同じ）はラッチをそのまま引き継ぐようにした。`rt_target_cp` は同じ値なので毎回代入している。

### 7. `07_RESOLVE_CONFLICT.vfl`：右折ブランチのゲート

```c
if (s@turn != "right" && i@rt_lookahead != 1) {
```

先読み中は、まだ `s@turn` が `"right"` でなくても右折車として判断を回す。直進車側の `passed` 判定（`s@turn == "straight"` の別ブロック）とは独立なので、手前のレーンにいる間は両方走る。

### 追加した属性

- `i@rt_lookahead`（`01_INIT.vfl` で0初期化）… 1=次のprimが右折コネクタ。コネクタに乗っている間も（`next_lane_name` が自分自身を指すため）1になるので、意味は「次が右折」であって「まだ乗っていない」ではない。使っているのは `07` のゲートだけで、コネクタ上では `s@turn == "right"` 側で通るため影響はない

## 確認すべきこと

- 右折開始の最初のフレームで `dbg_dcp` が数mではなく数十mになっていること（先読みが効いている）
- `i@rt_lookahead` が、交差点の手前のレーンにいる段階で1になっていること
- `dbg_go_reason` が 1（止まり切れない）のまま残る車がいないこと
- 進入レーンの点が `turn == "right"` を持つ場合、先読みでyieldが立った時点から `010_INTEGRATE.vfl` の `right_turn_speed` crawl（avgの15%）が交差点の手前から効く。徐行が長すぎるようなら `turn_limit` の条件を見直す
- `07` の `search_radius = 40` は先読みで自車が交錯点から遠ざかったぶん、相手を捕捉できる範囲が実質狭くなる。対向車を見つけられずに素通りする車がいたら、ここを広げる
