# 2026-09-22 スポーン直後に next_turn / next_lane_name が空になる

`s@next_turn`は`03_UPDATE_LANE_ATTRIB.vfl`の**`lane_changed`ブロックでしか作られない**。スポーン直後の車はまだ一度もレーンを乗り換えていないので、最初のレーンを走り切るまで`""`のまま走る。

この間、次に依存する処理が全部効かない。

- 右折の先読み（`i@rt_lookahead`）— 交差点に入る前に判断を始められない
- `06_CAR DETECT.vfl` / `07_RESOLVE_CONFLICT.vfl`の左折車除外 — 相手の`next_turn`が空だと一致しない
- `s@cross_lines` / `v[]@rt_target_cp` — 交錯点の情報そのもの

短いレーンで生まれた右折車ほど影響が大きい。

## 変更内容：01_INITで`lane_changed = 1`を立てる

`01_INIT.vfl`で`next_turn`を直接引くこともできるが、それだと「`next_lanes`を引く → 最寄り点 → primの`turn`」という解決を01と03の2箇所に持つことになる（`KNOWLEDGE/Houdini運用メモ.md`「同じ関係を複数の経路で導出しない」）。フラグを立てて03に1回引かせる。

```c
i@lane_changed   = 1;
s@next_lane_name = "";
```

ノード順は01→02→03なので、スポーンした最初のフレームの03で解決が終わる。02は`next_lane_name`が空だと乗り換えないので、その1フレームは何も起きない（スポーン位置は`u`が小さく、そもそも乗り換え条件に達しない）。

`___SPEC.md`（旧アーキテクチャ）が`lane_changed=1`をINITに置いていたのと同じ形。`OVERVIEW/Overview.md` 3.1の注記にあった「初期化ギャップ」の片側が埋まった。

## 前提と失敗時の挙動

`s@lane_name`がスポーン時に入っていることが前提。空だと03の`nearpoint`が解決できず、`lane_changed`が1のまま毎フレーム再試行を続ける（`___SPEC.md`のリトライパターン。エラーは出ない）。

スポーン点に`lane_name`が乗っているかは、車を1台出して`s@lane_id`と`s@next_turn`が1フレーム目で埋まるかで確認できる。

## 確認すること

- スポーンした車が、最初のレーンにいる時点で`s@next_turn`と`i@rt_lookahead`を持っているか
- スポーン直後の右折車が、交差点の手前から譲る判断を始めるか（従来は交差点に入ってからだった）
