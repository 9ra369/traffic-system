# 右折 vs 直進 コンフリクト解決 — 修正の流れ

モックアップ（HTML）を詰めていった経緯と、各修正の理由。最終仕様は `right-turn-spec.md` を参照。

---

## 時系列

1. **初版**：上から見た交差点。右折車が検索コーン（相手の `dir` との内積）＋到達時間比較で停止/減速/進行を判断するインタラクティブUI。

2. **UIのがくがく解消**：検出リストを毎フレーム全再構築 → 行を使い回す方式に。DOM更新を間引き。あわせて `search_radius` をコントロール化。

3. **リストの折りたたみ＋固定高さ**：行数変化でカード高さが変わり下が揺れる問題を、固定高さスクロールで解消。

4. **判定文の1行固定**：「塞がれている」表示が2行折返しで揺れる → 1行固定＋省略。

5. **直進車に通過フラグ `ahead_intersect`**：cp を通過した直進車は右折車の検知対象から除外。

6. **右折車に前方判定 `dot(dir, →相手) ≥ 0.5`**：後方の車を拾わないように（相手の `dir` だけのコーンでは後方を弾けなかった）。

7. **直進車に「前を右折車が横切っていたら停止」**：優先でも衝突回避。譲って待つ右折車には反応しないレーン帯ガードで膠着回避。

8. **直進車の判定を内積＋距離方式へ**：`dot(dir, →右折車)` と右折車までの距離（減速/停止）で整理。

9. **内積 0.8 → 0.65、通過フラグ・膠着ガード整備**：0.8では停止圏に入らず止まれなかったため緩和。

10. **検知は右折開始後のみ**：直進の進入区間では検知しない（仕様準拠）。

11. **右折中は徐速**：カーブ中は巡航×`turnCreep` に。

12. **停止/減速距離を減速度から自動導出（物理式 `d = vτ + v²/2a`）を試作**：理屈は正しいが、速度連動で距離が動きチューニングが不安定に（＝破綻気味）。

13. **手動距離方式に戻す（stop 5.5 / decel 12.0）＋「検知した瞬間に yield/go を確定して保持」**：毎フレームの判定ブレによる「中途半端に進む」を解消。直進車の防御ガードも右折車の確定判断基準に統一。

14. **判断を単一TTCしきい値に**：距離×速度の箱ルールは隙間・境界矛盾が出るため、`t_other ≥ 3.5s なら go / 未満なら yield` の1本に。平面を隙間なく被覆。

15. **減速度の設定を追加**：減速ゾーン=快適減速、停止ゾーン=緊急減速、発進=加速、を個別に。

16. **直進車は「向かってくる時だけ」判断／go は途中停止しない／停止位置は cp より手前**：直進車は「前方かつ動いている右折車」だけに反応。go 確定後は止まらず抜ける。停止線で頭出しを防止。

17. **停止線を越えたら通過へ切替**：止まり切れず線を越えたら `go` に切替えて抜け切る（交錯点で固まらない）。動いて抜ければ向かってくる直進車が止まって受ける。

18. **判断保持の条件を「コーン内にいるか」→「未通過・半径内に対象車が1台でもいるか(`anyCandidate`)」に変更、goからyieldへの昇格を追加**：自分の向き `dir` がカーブ中に回転するせいで、コーン／前方判定から一瞬だけ外れて `decided` がリセットされ、止まって譲っている右折車が一瞬進み出してまた止まる、という挙動があった。判断を保持する条件を緩め、真に周囲に対象車がいなくなったときだけリセットするよう修正。あわせて、`go` と確定した後でも新たに到達時間の短い車が現れたら即座に `yield` へ昇格できるようにした（従来はコーンが一度完全に空にならないと再判定されず、車列が途切れないと新しい危険な車を見逃す穴があった）。`yield` はこのラッチでは `go` に戻さない（安全側は自動で緩めない、`go` に戻すのは停止線越えのときだけ）。

19. **#18の副作用で「進もうと思ったら途中でまた止まる」が発生 → 車ごとに初見の瞬間だけTTCを評価して保持する方式に修正**：#18の「goの後でも`blocked`が真になったらyieldへ昇格」は、`blocked`を毎フレームその場のTTCで再計算していたため、既に見えていた車が単に近づいてTTCが閾値を割っただけでも「新しい危険な車が現れた」と誤認して昇格してしまっていた（等速接近する車のTTCは時間経過分だけ単調に減るので、しきい値付近でgoと確定した車はほぼ確実に直後に閾値を割る）。修正として、各車に `seenByEgo`/`blockingEgo` を持たせ、**その車が初めてコーンに入った瞬間のTTCだけで blocking を確定し、以後はその車が交点を通過するまで再評価しない**ようにした。go→yieldの昇格は「本当に未評価だった車が、初めて見えた時点で既にblocking」の場合だけ起きるようになり、既知の車のTTC減衰では起きなくなった。右折車がターンを再開する際（`resetEgo`）は全車の評価をリセットして仕切り直す。

## 設計上の学び

- 2変数（距離・速度）を箱で切ると隙間と境界矛盾が出る → **本質は到達時間 TTC**。単一しきい値で被覆する方が破綻しない。
- 「いつ反応するか（距離しきい値）」と「どれだけ強く止まるか（減速度）」は分けて持つと調整しやすく、緊急減速が快適減速の取りこぼしを拾う二段構えは頑健。
- **判断は検知の瞬間に確定して保持**すると、毎フレーム再評価による震え（中途半端な挙動）が消える。
- 交錯点は**居座らないのが最優先**。手前で止まる／無理なら抜け切る、の二択にし、相手（優先側）の保険的減速で受ける。
- **「判断を保持する条件」と「判断の中身を決める条件」は別物にする**：保持は緩く（対象車が本当にいなくなるまで＝`anyCandidate`）、確定の中身はコーン＋TTCで絞る。両方を同じ条件（コーン内か）でやると、自分の向きの回転などのノイズでラッチが暴れる。
- **安全側（yield）への切替はいつでも許可、緩める側（yield→go）は限定的な条件でしか許可しない**、という非対称なラッチが頑健。今回は「go中でも危険な車が現れたらyieldへ即昇格」「yieldは停止線越え以外では自動でgoに戻さない」という形にした。
- **「毎フレーム再評価」は一見自然に見えても、等速接近する相手のTTCが時間経過だけで単調に減っていく以上、しきい値付近の判定は必ずすぐ反転する**。再評価してよいのは「まだ見ていない対象が新しく現れたとき」だけで、既に見た対象は接近してTTCが減っても再評価しない（初見の瞬間の値で固定する）のが正解。判断ロジックに時間経過で自然に変化する量（距離・TTC）を条件に使うときは、それが「新規発生」なのか「既知の状態の自然な推移」なのかを区別すること。
