# 右折時の交錯点におけるコンフリクト回避

note記事用の本文。実装の現状（[[07_RESOLVE_CONFLICT]] / [[03_UPDATE_LANE_ATTRIB]] / [[06_CAR DETECT]]）に合わせて2026-09-21に更新。

## 本文

**なぜIDMのような追従モデルが使えないのか**

IDMは「自分のすぐ前を走る1台」との車間距離と相対速度から加速度を決めるモデルです。前提として、自分と相手が同じ進路上に並んでいて前後関係がはっきりしていることが要ります。ところが下図のように、右折レーンと直進レーンは**交錯点で一瞬だけ交わる**だけで、それまでは別々のレーンを走っています。相手は自分の前にいるわけではないので、車間距離という量がそもそも定義できません。見るべきなのは「相手と自分の距離」ではなく「**それぞれが交錯点に着くまでの時間**」です。

（図：右折レーンと直進レーンの交錯点）

（進路を横切ってきた車を前車として扱う汎用の検知は別に持っていますが、あれは目の前に出てきた車にとりあえず反応する保険で、どちらが先に行くかを決めるものではありません。）

**判断：自車の到達時間との相対比較**

そこで右折車は、自分が交錯点に着くまでの時間 `t_ego` と、対向直進車が着くまでの時間 `t_other` を等加速度運動の式で出し、`t_other < t_ego + 余裕` なら譲る（yield）と判断します。固定のTTCしきい値ではなく自車の到達時間との相対で見るのは、すでに交錯点へ進入しかけている車にまで一律の閾値で急ブレーキを要求すると、物理的に不可能な減速になってしまうためです。また、相手が一瞬アクセルを緩めただけで「もう来ない」と判断しないよう、`t_other` は減速を織り込んだ値と等速で来た場合の値の**早いほう＝安全側**を採ります。逆に、停止線が交錯点より手前にあって「信号で止まると分かっている車」は、交錯点まで来ないので候補から外します。

**判断は非対称にラッチする**

フレームごとに判断が揺れないよう、結果はラッチしますが、緩める向きと締める向きで扱いを変えています。go→yield（安全側）への切り替えはいつでも許し、yieldは自動ではgoに戻りません。解除されるのは、相手候補が一定フレーム連続で消えたときか、「もう止まり切れない／すでに交錯点上にいる／通過し終えた」という**交錯点との位置関係から決まる例外**だけです。最後の例外は「交錯点上に居座らない」ための処理で、間に合わないと分かった時点で止まらずに抜け切ります。

一方、**相手の車を1台にロックすることはしません**。初めて見た1台に固定すると、その後ろに続く対向車が先頭が抜けるまで一度も評価されず、先頭が抜けた瞬間に判断が入れ替わってチラつきます。毎フレーム候補を集め直し、最も早く交錯点に来る1台で代表させています。相手が交錯点を抜けたかどうかも、相手が自分で立てるフラグに頼らず、交錯点座標への符号付き射影でこちら側から毎フレーム見ます（先端が越えた瞬間ではなく、車体が抜け切るぶんの余裕を持たせて外します）。

**交錯点の情報はレーン側に焼いておく**

交錯点の座標は道路形状だけで決まる値なので、道路網の生成時にレーンのプリム属性として焼き込み、右折車はレーン名で直接引きます。近くにいる直進車から読む設計だと、対向車がまだ1台もいない瞬間に値が不安定になるためです。判断を始めるのも右折コネクタに乗ってからでは遅い（交錯点まで数mしかなく止まれない）ので、次に曲がると決めた時点で1つ手前のレーンから先読みします。

そして、1本の右折レーンが複数の直進レーンと交わる場合は、`cross_lines` が持つ**lane_nameごとに判断状態を独立**させることで、別の交錯点の判定を誤って参照しないようにしています（合流地点で `lane_id` により隣のスプラインの `@dir` を誤取得しないようにしているのと同じ考え方です）。

## 旧稿から直した点（事実が変わっていたところ）

| 旧稿の記述 | 現状 |
|---|---|
| 「初めて検知した瞬間のTTCだけで一度確定し、以後再評価しない」 | 相手車はロックしない。毎フレーム全候補を評価して最短 `t_other` で代表。ラッチしているのは判断結果（yield→goに自動で戻さない）だけ |
| 「その車が交錯点を通過する（`passed==1`）まで」 | `passed` は右折車側では使っていない（現状デバッグ用）。解除条件は「候補が一定フレーム消えた」か、交錯点との位置関係による例外（止まり切れない／交錯点上／通過済み） |
| 「TTCで」 | 固定TTC閾値ではなく `t_other < t_ego + margin` の相対比較 |
| 「`cross_lines` が持つ `lane_id` ごと」 | `lane_name` ごと（照合を lane_name に統一済み） |
| 「合流地点で `road_id` により」 | `road_id` はコード上に存在しない。現在は `lane_id` で絞っている |
| 交錯点＝`cross_pos` を右折車が見る | 右折車は交錯レーンごとに焼いた固定座標を引く（車個体に依存しない） |

追記したのは、IDMが使えない理由の本文（旧稿では見出しだけのプレースホルダ）、信号で止まる対向車の除外、1つ手前のレーンからの先読み。
