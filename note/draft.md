6. Houdiniで実装することの意味

Web のほうが速く、ユーザーフレンドリー

正直に言うと、今回 Houdini を選んだ理由の多くは主観的なものです。3DCG が好きであること、単純に Houdini に使い慣れていること。ただ、それだけを理由にすると「3DCG こそ正しい手段だ」と思い込んでしまい、本来あったはずの他の選択肢を見落としてしまいます。そこで試しに「このシステムを HTML で実装して」と Claude に頼んでみたところ、すぐにこれだけのものが返ってきました。車線数の変更や道路の追加・編集もできるので、よければ触ってみてください。

図13. ウェブ版交通システム

正直、こちらのほうが分かりやすく、直感的です。実装についても、すでにあるシステムの設計書を渡して何度かやり取りするだけで、ここまで形になりました。仕様を一から自分で詰めたものを渡しているので今の AI の水準を考えれば妥当な結果ではありますが、Web のほうが参照できる情報量が圧倒的に多いぶん、体感としても早く終わりました。

それでも Houdini で作る理由

では、なぜわざわざ Houdini で実装したのか。扱っているのが 3D データだからです。見せ方の手軽さでは Web に譲ります。ただ、3D データをそのまま成果物として生み出せるのは Houdini のような DCC ソフトの側です。ジオメトリの生成や交差判定、法線やオフセットの扱いといった処理は既存ノードがそのまま使えるので、同じことを一から実装するのに比べれば、考えることも書くことも圧倒的に少なくて済みます。

つまり、UI として見せるなら Web、3D データとして作るなら Houdini、というのが自分の中の住み分けです。そして今回は、後者がこのシステムの目的そのものだったので、Houdini を選びました。この「3D データとして作る」という選択が、次に述べる展望の前提にもなっています。

7. 今後の展望

このプロジェクトは、もともと興味本位で始めたものです。
ただ、AI によって個人でも扱える範囲が急速に広がっている今、CG の使い道をエンタメだけに絞る必要はないとも感じています。
ゲームや映画の背景としての活用はもちろん、デジタルツインのように都市計画やシミュレーションへ寄せていく方向性も、選択肢の一つとして探っていきたいと考えています。
とはいえ、そのために大きな計画があるわけではありません。
まずは個人として、面白いと思えるものを日々作っていくつもりです。
手を動かしながら考え、考えながらまた手を動かす——その繰り返しの中で、次に何を作るかを決めていきたいと思います。
この交通システムも、そうした試みの一つです。
