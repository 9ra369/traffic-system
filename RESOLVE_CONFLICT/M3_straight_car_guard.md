# M3: 直進車 → 右折車の検知アルゴリズム（検討の結果、不要と判断）

## 結論

**専用の実装は不要。** 既存の [[06_CAR DETECT]] が持つ `is_cross` 判定（前方コーン`cross_dot>=0.7` ＋
横オフセット`cross_half_w<=2.0m`で「自分の進路を横切っている車」を検知する仕組み）が、実質的に
右折車の飛び出しに対する保険的減速の役割を代わりに果たす。`cross_lines`/`cross_curve`を使った
lane_id指定の専用検索は追加しない。

## 判断の理由

1. **`06_CAR DETECT`が既に同じことをしている。** `is_cross`はレーンの種類（右折/直進）を問わず、
   「自分の前方・進路上を横切っている車」を幾何的に検知して`dist_to_car`/`car_vel`に反映する
   汎用の仕組み。右折車が実際に直進レーンへ進入してくる場面は、まさにこの条件（前方＋横オフセット
   小）に当てはまるので、狙って作らなくても捕捉される。
2. **膠着（デッドロック）が再発しない。** [[M2_right_turn_search]]の設計では、右折車は
   「交錯点の手前で止まるか、止まり切れなければ止まらず抜け切る」（`commit_dist`／停止線ルール）
   ため、**直進レーンの進路上（＝`is_cross`が反応する横オフセット圏内）で右折車が停止したまま
   でいることはない**。つまり`is_cross`が反応する時点で、その右折車は必ず動いている
   （通過中）ので、[[right-turn-changelog]] #7・#16 で気にしていた「止まって譲っている車に
   反応して膠着する」問題は起こらない。
3. **横幅の整合性もおおむね取れている。** 道路幅3.5mに対し`cross_half_w=2.0m`（半分は1.75m相当）
   なので、既存の定数のままでも大きくズレていない。気になるなら`cross_half_w`を1.75〜2.0m程度に
   寄せる微調整はアリ（優先度低）。

## この判断が崩れる条件（再検討が必要になるケース）

- M2の「交錯点手前で止まる」ルールが崩れて、右折車が直進レーンの進路上に停止したまま
  になり得る設計に変わった場合 → 上記2の前提が崩れるので、このM3を復活させる必要がある
- `is_cross`の反応が遅すぎる（横切り始めてから気づくのでは遅い、もっと手前から予測的に
  減速したい）と実機で判明した場合 → RESOLVE_CRUSHの直進車ガード（[[right-turn-spec]] 4章）の
  ような、より早期の検知ロジックを別途足す

2. `passed==1`（M1で通過済み）の自分は、この処理自体をスキップする
3. 候補の右折車について、前方にいるか（`dot(dir, →右折車)`）と実際に動いているか（`vel > 0.5`）を
   両方満たす場合だけ反応する
4. 距離に応じて停止／減速

`egoComing = vel > 0.5`による「動いている車にだけ反応する」膠着回避の考え方自体は正しく、
`is_cross`にも間接的に同じ効果（停止中の右折車は横オフセット圏内に来ない）が備わっている。
